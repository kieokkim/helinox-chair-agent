## 모든 답변 공통

1. Be direct and concrete
   - 추상적 서술 대신 숫자와 파일명으로 말할 것
   - 예: "표본 부족" (X) → "48건 있는데 144건 필요, 3배 모자람" (O)

2. Show all intermediate states
   - 결론만 주지 말고 그 숫자가 나온 사이 계산을 전부 노출할 것
   - 예: "7.2년 필요" (X) → "81건이 4년치 → 연 20건 → 144÷20 = 7.2년" (O)

3. Explain like I'm 12
   - 어려운 용어는 지우지 말고, 옆에 쉬운 말을 괄호로 붙일 것
   - 예: "bootstrap CI가 0을 포함 (= 데이터를 만 번 다시 섞어봐도
     '수익이 0일 가능성'을 매번 못 지웠다는 뜻)"
   - 용어 자체를 바꾸면 내 문서와 대화가 따로 놀기 때문에 이름은 유지할 것
