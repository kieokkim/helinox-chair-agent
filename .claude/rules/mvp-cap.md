## MVP 상한

### plan 문서 첫 3줄 고정
docs/plan_{작업명}.md 는 다음 3줄로 시작한다. 하나라도 없으면 구현 진입 금지.

  목표:      (사용자가 쓴다. 왜 만드는가. 1문장)
  종료 조건: 입력 N개 중 M개를 X 기준으로 통과하면 끝
  시작 시각: YYYY-MM-DD HH:MM  (구현 진입 시 date로 기록)

### 시간
- 총 8시간. 배분 research 1h / plan 1h / 구현 5h / 회고 1h
- 각 단계 진입 시 `date`를 실행해 경과를 계산하고 1줄 보고한다.
  형식: "경과 2h10m / 8h. research+plan 배분 2h 대비 +10m."
- 8h 도달 시 완성 여부 무관하게 중단.
  git tag mvp-stop-{작업명} → 회고 1장 → 종료.

### 목표 변경 제안
목표는 사용자가 정한다. research·plan에서 목표와 어긋나는 사실이 나오면 제안한다.

- 제안 시점은 2곳뿐: research 문서 마지막, plan 문서 마지막.
  구현 중에는 제안하지 않는다.
  예외 1개 — 종료 조건 자체가 측정 불가능해진 경우.
- 제안 형식 4줄 고정:
    관측:   (파일명:행 근거)
    영향:   목표 또는 종료 조건의 어느 부분이 성립하지 않는가
    선택지: A 목표 유지 + 범위 축소 / B 목표 수정 / C 중단
    재배분: 각 선택지의 남은 시간 배분을 숫자로
- 제안 후 멈춘다. 사용자 응답 전 진행 금지.
- 게이트당 1회. 같은 건으로 반복 제안하지 않는다.

### 판단 경계
- 한다:    관측 보고, 선택지 나열, 시간 재계산
- 안 한다: "이 정도면 충분하다" / "B가 낫다" / 선택지 중 추천
